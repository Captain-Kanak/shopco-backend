## Conventions

These conventions apply consistently across the schema unless a model explicitly states otherwise.

| Convention       | Details                                                                                                                                                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Primary keys** | `String @id @default(uuid(7))` — UUIDv7, time-sortable, on every model except auth tables (see note below).                                                                                                                                                                    |
| **Timestamps**   | `createdAt`, `updatedAt` on every model. `deletedAt` on every model that supports soft delete.                                                                                                                                                                                 |
| **Soft delete**  | Rows are never hard-deleted from soft-delete-enabled models; `deletedAt` is set instead. Application code (not the database) is responsible for filtering out soft-deleted rows and for cascading soft-deletes to child records — see [Known Limitations](#known-limitations). |
| **Money fields** | `Decimal @db.Decimal(10, 2)` — never `Float`, to avoid floating-point rounding errors on currency.                                                                                                                                                                             |
| **Table naming** | Every model maps to a `snake_case` table name via `@@map(...)`.                                                                                                                                                                                                                |

> ⚠️ **Auth tables and UUID generation:** `User`, `Session`, `Account`, and `Verification` are managed by [Better Auth](https://better-auth.com), which generates its own row IDs at insert time — Prisma's `@default(uuid(7))` never actually fires for rows Better Auth creates, since Better Auth supplies an explicit `id` on every insert. By default, Better Auth generates a 32-character random alphanumeric string (not a UUID) for non-Postgres adapters, and defers to the database's own UUID generation on Postgres. To keep IDs consistent with the rest of this schema, `advanced.database.generateId` is configured in the Better Auth setup to produce UUIDv7 values matching every other table. See `src/config/auth.ts`.

## Auth Models

### User

Core account record. Managed by Better Auth for creation/authentication; referenced by the rest of the app for orders, carts, and payments.

| Field                                   | Type             | Description                                                                                                         |
| --------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| `id`                                    | `String` (PK)    | Generated by Better Auth (see note above).                                                                          |
| `name`                                  | `String(100)`    | Display name.                                                                                                       |
| `email`                                 | `String(255)`    | **Unique.** Not editable via the profile-update route — email changes require a separate re-verification flow.      |
| `emailVerified`                         | `Boolean`        | Defaults to `false`.                                                                                                |
| `image`                                 | `String?`        | Cloudinary URL of the profile picture.                                                                              |
| `phone`                                 | `String(15)?`    | Optional.                                                                                                           |
| `address`                               | `String?` (Text) | Optional. Free-text; not structured into city/district/postal fields — see [Known Limitations](#known-limitations). |
| `dateOfBirth`                           | `DateTime?`      | Optional.                                                                                                           |
| `role`                                  | `UserRole`       | Defaults to `CUSTOMER`. Never editable through a self-service route.                                                |
| `status`                                | `UserStatus`     | Defaults to `ACTIVE`. Admin-only field.                                                                             |
| `createdAt` / `updatedAt` / `deletedAt` | `DateTime`       | Standard timestamps.                                                                                                |

**Relations:** `carts[]`, `orders[]`, `payments[]`, `sessions[]`, `accounts[]`

**Indexes:** `@@unique([email])`, `@@index([deletedAt])`

### Product

Parent catalog entity. Holds descriptive content only — price, stock, and purchasable options live on `ProductVariant`. Every product must have at least one variant, even if it has no real customer-facing options, so that price/stock logic never needs a "does this product have variants" branch in application code.

| Field                                   | Type                   | Description                                                                       |
| --------------------------------------- | ---------------------- | --------------------------------------------------------------------------------- |
| `id`                                    | `String` (PK)          | UUIDv7.                                                                           |
| `title`                                 | `String(200)`          |                                                                                   |
| `slug`                                  | `String(255)`          | **Unique.**                                                                       |
| `description`                           | `String` (Text)        |                                                                                   |
| `discountPercentage`                    | `Int`                  | Defaults to `0`. Not DB-constrained to 0–100; validate at the application layer.  |
| `status`                                | `ProductStatus`        | Defaults to `DRAFT`. Controls storefront visibility independently of `deletedAt`. |
| `brandId`                               | `String?` (FK → Brand) | Optional — a product does not require a brand. `onDelete: SetNull`.               |
| `createdAt` / `updatedAt` / `deletedAt` | `DateTime`             | Standard timestamps.                                                              |

**Relations:** `productCategories[]`, `variants[]`, `images[]`

**Indexes:** `@@unique([slug])`, `@@index([brandId])`, `@@index([status])`, `@@index([deletedAt])`

### ProductVariant

The actual purchasable unit — carries its own SKU, price, and stock. Distinguishing options (size, color, storage, etc.) are stored generically via `ProductAttribute` rather than fixed columns, so the same schema supports any product category.

| Field                                   | Type                    | Description                                                                                                                                                                   |
| --------------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                                    | `String` (PK)           | UUIDv7.                                                                                                                                                                       |
| `sku`                                   | `String(255)`           | **Unique.**                                                                                                                                                                   |
| `price`                                 | `Decimal(10,2)`         |                                                                                                                                                                               |
| `compareAtPrice`                        | `Decimal(10,2)?`        | "Was" price, for showing a discount strike-through.                                                                                                                           |
| `stock`                                 | `Int`                   | Defaults to `0`.                                                                                                                                                              |
| `weightGrams`                           | `Int?`                  | Reserved for future shipping-cost calculation.                                                                                                                                |
| `version`                               | `Int`                   | Defaults to `0`. **Optimistic lock** — increment on every stock update; reject/retry if the expected version doesn't match, to prevent overselling under concurrent checkout. |
| `productId`                             | `String` (FK → Product) | `onDelete: Cascade`                                                                                                                                                           |
| `createdAt` / `updatedAt` / `deletedAt` | `DateTime`              | Standard timestamps.                                                                                                                                                          |

**Relations:** `attributes[]`, `images[]`, `carts[]`, `orderItems[]`

**Indexes:** `@@index([productId])`, `@@index([deletedAt])`

### ProductAttribute

Generic key/value option per variant. Replaces a hardcoded size/color enum so the schema is reusable across product categories (apparel, electronics, groceries, etc.).

**Examples:** `("Size", "L")`, `("Color", "Red")`, `("Storage", "256GB")`

| Field                     | Type                           | Description                    |
| ------------------------- | ------------------------------ | ------------------------------ |
| `id`                      | `String` (PK)                  | UUIDv7.                        |
| `name`                    | `String(100)`                  | Attribute name, e.g. `"Size"`. |
| `value`                   | `String(255)`                  | Attribute value, e.g. `"L"`.   |
| `variantId`               | `String` (FK → ProductVariant) | `onDelete: Cascade`            |
| `createdAt` / `updatedAt` | `DateTime`                     | Standard timestamps.           |

**Indexes:** `@@unique([variantId, name])` — a variant cannot have two values for the same attribute name. `@@index([variantId])`

### OrderItem

A historical snapshot of a single purchased line item. Fields like `productTitle`, `sku`, and `unitPrice` are deliberately duplicated from the live catalog rather than joined live, so a past receipt never changes if the product is later renamed, re-priced, or deleted.

| Field                                   | Type                           | Description                                                                                   |
| --------------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------- |
| `id`                                    | `String` (PK)                  | UUIDv7.                                                                                       |
| `sku`                                   | `String(255)`                  | Snapshot of the variant SKU at purchase time.                                                 |
| `productTitle`                          | `String(255)`                  | Snapshot of the product title at purchase time.                                               |
| `unitPrice`                             | `Decimal(10,2)`                | Snapshot of the price paid — independent of any later price change.                           |
| `quantity`                              | `Int`                          | Defaults to `1`.                                                                              |
| `orderId`                               | `String` (FK → Order)          | `onDelete: Cascade`                                                                           |

**Indexes:** `@@index([orderId])`, `@@index([variantId])`, `@@index([deletedAt])`

## Known Limitations

Documented deliberately rather than silently — these are open decisions, not oversights, and should be revisited as the product matures.

1. **Soft delete vs. `onDelete: Cascade` conflict.** Several relations use `onDelete: Cascade` (e.g. `Product → Brand`, `Cart → ProductVariant`), which only fires on a genuine SQL `DELETE`. Since most deletions in this app are soft deletes (`deletedAt`), cascading children are **not** automatically soft-deleted when a parent is. Cascading a soft-delete down a relation tree must currently be handled explicitly in the service layer.
2. **Unique constraints ignore soft-deleted rows.** `Brand.slug`, `Category.slug`, `Product.slug`, and `User.email` are globally unique, including against soft-deleted rows — e.g. a soft-deleted brand permanently blocks reuse of its slug. A partial unique index (`WHERE "deletedAt" IS NULL`) would resolve this but requires a raw SQL migration, since Prisma's schema language does not support partial indexes natively.
3. **`Payment.transactionId` is required.** Cash-on-delivery orders typically have no transaction ID at creation time. This field should likely become optional (`String?`).
4. **`Payment` is 1:1 with `Order`.** This prevents recording a history of retried or failed payment attempts (e.g. a failed Stripe charge followed by a successful retry) — only the single current payment can be stored.
5. **`User.address` and `Order.shippingAddress` are unstructured free text.** Neither is split into city/district/postal-code fields, which limits shipping-cost calculation by region or integration with courier APIs in the future.
6. **No dedicated `Review`, `Wishlist`, `Coupon`, or `StockMovement` models yet.** These are common ecommerce features not yet represented in the schema.
